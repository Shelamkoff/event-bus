# @shelamkoff/event-bus

Небольшая синхронная шина событий без внешних зависимостей для браузерных библиотек и Node.js. События передаются в пределах одного JavaScript-окружения, без взаимодействия между процессами, воркерами или вкладками браузера.

[English README](./README.md)

## Требования и установка

- окружение с поддержкой модулей ECMAScript;
- Node.js 20 или новее при использовании в Node.js;
- внешние зависимости отсутствуют.

```bash
npm install @shelamkoff/event-bus
```

## Быстрый старт

```ts
import { EventBus } from '@shelamkoff/event-bus'

interface EditorEvents {
  ready: [documentId: string]
  change: [version: number]
  close: []
}

const events = new EventBus<EditorEvents>()
const unsubscribe = events.on('change', version => {
  console.log('Версия документа:', version)
})

events.once('ready', documentId => console.log('Готов:', documentId))
events.emit('ready', 'document-1')
events.emit('change', 2)

unsubscribe()
events.clear()
```

Тип карты событий необязателен, но рекомендуется при использовании TypeScript. Каждому событию соответствует кортеж аргументов, которые принимает `emit()` и получает обработчик. Если переменная имени события имеет тип объединения с несовместимыми аргументами, перед вызовом `emit()` её необходимо сузить.

## Программный интерфейс

| Элемент | Поведение |
| --- | --- |
| `new EventBus({ debug?: boolean })` | Создаёт независимую шину. `debug: true` выводит отправляемые события через `console.log`. |
| `on(event, handler)` | Регистрирует обработчик и возвращает идемпотентную функцию отписки. Повторный `on()` с той же функцией использует одну подписку; любая из возвращённых функций может её удалить. Старая функция отписки не удаляет новую регистрацию. |
| `once(event, handler)` | Регистрирует независимый обработчик на один вызов и возвращает функцию отписки. Повторные вызовы `once()` с одной функцией создают независимые подписки. |
| `off(event, handler)` | Удаляет все регистрации исходной функции, включая созданные через `once()`. Отсутствующий обработчик игнорируется. |
| `emit(event, ...args)` | Синхронно вызывает текущие обработчики в порядке регистрации. Возвращает `void`. |
| `has(event)` | Показывает, есть ли у события хотя бы один обработчик. |
| `clear(event)` | Удаляет все обработчики одного события. |
| `clear()` | Удаляет все обработчики из шины. |

Имя события должно быть непустой строкой, а обработчик — функцией. Нарушение этих требований приводит к `TypeError`.

## Семантика отправки событий

`emit()` вызывает обработчики **синхронно** в порядке регистрации и возвращает `void`. При отправке создаётся снимок подписок. Изменение подписок не влияет на этот снимок: в частности, удаление обработчика не отменяет его вызов, если он уже попал в снимок. При последующих отправках, в том числе вложенных, используется актуальный набор подписок.

Каждая регистрация `once()` независима от остальных. Она помечается использованной **до** вызова обработчика; повторный вызов той же одноразовой подписки при рекурсии невозможен.

Ошибки отдельных обработчиков изолированы:

- Синхронное исключение перехватывается и выводится через `console.error`; остальные обработчики продолжают выполняться.
- Возвращённые Promise и thenable **не ожидаются**. Их отклонения отслеживаются и асинхронно выводятся в `console.error`, чтобы избежать необработанных отклонений.
- Если сама регистрация ошибки или вывод при `debug: true` выбрасывает исключение, сбой логирования подавляется и не прерывает отправку.

Вывод ошибок осуществляется по возможности: API не возвращает ошибки и не предоставляет настраиваемый обработчик ошибок. Если издатель должен получить ошибки или результаты обработчиков, нужен отдельный асинхронный координатор на уровне приложения.

## Освобождение ресурсов

Сохраняйте и вызывайте функцию, возвращаемую `on()` или `once()`, если срок жизни подписчика короче срока жизни шины. Отписка привязана к конкретной регистрации и не затрагивает новую подписку после `off()`, `clear()` или повторного `on()`. Используйте `clear()` только тогда, когда владелец намеренно освобождает всех подписчиков.

## Разработка и проверки

Из отдельного клона репозитория:

```bash
npm ci
npm run check
npm pack --dry-run
```

Команда `npm run check` выполняет тесты Node.js, строгую проверку типов TypeScript и сборку пакета. GitHub Actions выполняет те же проверки на Node.js 20, 22 и 24. Версия исходного кода определяется по `package.json`; изменение репозитория само по себе не публикует новую версию в npm.

## Демонстрационный пример

Для запуска автономной демонстрации:

```bash
npm run demo
```

Откройте `http://127.0.0.1:4173/` (страница `index.html`). Порт можно изменить через `PORT`. Родительский workspace не требуется. Демонстрация не включается в публикуемый npm-пакет.
